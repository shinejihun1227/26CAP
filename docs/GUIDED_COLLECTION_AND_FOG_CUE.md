# 다섯 동작 수집과 FoG 지속 출력 사용법

## 업데이트 적용

1. PC에서 최신 `final` 브랜치 파일을 받습니다.
2. WROOM은 `firmware/stepon_c3/04_2_sta_bilateral_wroom/04_2_sta_bilateral_wroom.ino`를 엽니다.
3. `config.h`의 `STEPON_RIGHT_FOOT=0`으로 왼발에, `1`로 오른발에 각각 업로드합니다. 본인 `wifi_secrets.h`와 노트북 주소 `PC_HOST`를 확인하세요.
4. PC 프로그램을 종료한 뒤 `run.bat`을 실행합니다. 실행 중이라면 프로젝트 폴더 PowerShell에서 아래 명령으로 프로그램만 재시작할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\cap_web\tools\start-local-web.ps1 -Restart
powershell -NoProfile -ExecutionPolicy Bypass -File .\web\ai_bridge\start-ai.ps1 -Restart
```

5. 웹에서 Ctrl+F5를 누릅니다. 기기 설정에서 양발 연결과 개인 IMU 보정을 확인합니다.

펌웨어는 PC 코드 업데이트만으로 보드에 적용되지 않습니다. 양쪽 보드에 다시 업로드해야 합니다. 이 final 묶음의 펌웨어는 WROOM용이며 C3에는 사용할 수 없습니다.

## 다섯 동작을 모으는 방법

웹 **데이터 관리 → 다섯 동작 수집 안내 · CSV 분석** 또는 `http://127.0.0.1:8000/data/`로 이동하세요.

1. 참가자 코드(실명 대신 P001), 측정 회차, 측정 발과 실제 부착 위치를 입력합니다. 같은 사람은 같은 참가자 코드를 유지하세요.
2. **보정 25초 기록**: 버튼을 누르고 3초 준비 → 첫 5초 정지 → 20초 일반 보행. 완료 시 센서 단위·축·움직임·수신 품질을 검사합니다.
3. 동작 카드를 선택하고 기록 버튼을 누릅니다. 각 동작 시작 전 3초 준비 시간이 있고, 안내 시간이 끝나면 자동 저장됩니다.

| 동작 | 시간 | 수행 안내 |
|---|---:|---|
| 가만히 서기 | 30초 | 편하게 서서 움직이지 않기 |
| 평소처럼 걷기 | 60초 | 평소 속도로 걷기 |
| 천천히 걷기 | 60초 | 평소보다 천천히 걷기 |
| 걷다가 멈추기 | 60초 | 10초 걷기 → 5초 정지, 4회 반복 |
| 방향 바꾸며 걷기 | 60초 | 넉넉한 공간에서 좌·우 방향 전환을 포함해 걷기 |

한쪽 발의 동작 시간 합계는 보정 포함 4분 55초입니다. 각 기록 사이에 쉬어도 됩니다. 기록 중에는 참가자·발을 바꿀 수 없습니다. 센서 부착을 바꾸면 다시 보정하세요.

- **0/5 → 5/5**는 이번 참가자·회차·발·위치에서 완료된 동작 수입니다. 각 동작의 저장 횟수도 별도 표시합니다.
- 중간 정지, 연결 누락, 낮은 수집률, 보정 실패는 완료 횟수에 넣지 않습니다. 실패한 시도의 원본과 원인은 보관합니다.
- 새로고침 후에도 PC에 저장된 같은 회차 기록으로 진행 상황을 복원합니다. 새 회차를 시작하려면 회차 이름을 바꾸세요. 다른 발도 별도 보정 후 같은 과정을 진행합니다.
- 최신 완료 기록은 자동으로 분석에 연결됩니다. 지난 기록의 **분석에 연결**을 누르면 그 기록에 사용했던 보정도 함께 연결됩니다.
- **데이터 검사 → 모델 분석 시작**으로 시간별 점수를 확인하고 CSV·결과·기록 정보를 내려받습니다.
- 수집 보정은 CSV 분석용입니다. 실제 FoG 자동 출력을 사용하려면 **기기 설정 → 개인 기준 설정 · AI 보정**에서도 개인 IMU 보정을 해야 합니다.

### 무엇이 저장되나요?

원시 가속도(g, 중력 포함)·각속도(°/s)·장치 시각·참가자·회차·발·부착 위치가 CSV에 저장됩니다. 일반 보행 기록 메뉴의 1초 요약값과는 다릅니다.

기록 정보에는 수집 절차 버전, 선택한 동작, 완료 반복 번호, 보정 기록 ID, 수신 품질이 함께 남습니다. `label=planned_walking` 등은 **안내한 동작**이며 실제 수행 동작이나 FoG 정답을 자동 확정하지 않습니다. `ground_truth_status=unreviewed`로 보관합니다. 실제 관찰/영상 판독을 통해 구간별 정답을 따로 만들어야 합니다. 의도적으로 멈추기는 실제 FoG 정답이 아닙니다.

이 기능은 기록과 기존 모델 분석입니다. 자동 재학습·정확도 산출 기능은 아닙니다. 압력센서·카메라 값은 현재 RF/CNN 점수에 합산하지 않습니다. 원본 자료는 PC의 비공개 `.stepon-data/ai/datasets` 아래에 보관되며 Git에 올리지 않습니다.

## FoG를 감지하면 진동과 레이저를 유지합니다

```text
ESP32의 실제 IMU → PC 수집 서버 → 실시간 RF/CNN과 상태 판정
                                  ↓ 각 발의 confirmed 상태
ESP32 출력 명령 갱신 → DRV2605 지속 진동 + 레이저 유지
                                  ↓ 감지 해제 / 입력 무효 / 보정
                             진동과 레이저 끄기
```

- `confirmed`(신호 감지)인 발에만 두 출력을 유지합니다. 양발 모두 감지되면 양발에 출력합니다.
- 정상·주의·준비 중·개인 보정·센서 끊김에서는 FoG 자동 출력을 끕니다. 다섯 동작 CSV를 수집하는 동안에도 출력을 쉬어 수집 신호에 진동이 섞이지 않게 합니다.
- 명령은 약 0.4초마다 갱신합니다. 보드는 마지막 유효 명령 이후 **1.5초** 동안 갱신이 없으면 출력을 끕니다. Wi-Fi 단절과 센서 데이터 정지도 보드에서 확인합니다.
- PC가 제어하므로 웹 탭을 닫아도 동작합니다. **웹의 일시정지는 화면 갱신 기능**입니다. 출력을 멈추려면 **기기 설정 / 보행 측정 → 진동·레이저 자동 출력 중지**를 누르세요. 중지 설정은 PC 재시작 후에도 유지됩니다.
- 다시 시작은 **자동 출력 다시 켜기**입니다. 실제 출력을 보려면 양발 개인 IMU 보정과 최신 펌웨어가 필요합니다. 버튼이나 웹 표시만으로 실제 모터·레이저 작동을 검증한 것은 아닙니다.
- CSV를 올려 분석하는 기능은 출력 명령을 보내지 않습니다.
- 기존 압력·자이로 규칙의 자동 진동은 제거했습니다. `/api/auto-cue`는 안내 오류를 반환하고 실제 AI 제어는 `/api/fog-cue`를 사용합니다.
- 수동 진동·레이저 테스트는 짧게 동작합니다. FoG 지속 출력과 구분하세요.

### WROOM 배선과 설정

| 연결 | GPIO |
|---|---:|
| I²C SDA / SCL (BMI270, DRV2605 등) | 13 / 14 |
| 압력 MUX S0 / S1 / S2 / S3 | 32 / 33 / 4 / 26 |
| 압력 MUX SIG | 34 |
| 압력센서 채널 | C0 / C2 / C4 / C6 |
| 레이저 출력: 베이스 저항 → 2N2222 | 27 |

`ENABLE_LASER_OUTPUT=true`로 설정했습니다. 기존 트랜지스터 구동 회로를 사용하며 GPIO에서 레이저 부하에 직접 전원을 공급하지 않습니다. DRV2605는 I²C 0x5A이며, 지속 진동은 RTP 모드 `FOG_VIBRATION_LEVEL=70`입니다. 센서 읽기와 DRV 제어는 같은 작업에서 실행해 I²C 충돌을 피합니다.

구형 펌웨어에서는 ‘최신 펌웨어 필요’ 오류가 표시되고 지속 출력 명령을 보내지 않습니다. 장치 ID와 부팅 ID가 맞지 않는 명령도 거부합니다.

## 적용 후 확인 순서

1. 기기 설정에서 실제 IMU 연결과 DRV2605 상태, 개인 보정을 확인합니다.
2. 수동 진동·레이저 테스트로 기존 배선에서 각 출력이 작동하는지 확인합니다.
3. 실제 실시간 AI 상태와 출력 상태를 함께 관찰합니다. 임의 동작을 실제 FoG 정답으로 기록하지 마세요.
4. 자동 출력 중지와 재시작 버튼을 확인합니다. 네트워크/PC를 끊었을 때 출력이 남지 않는지도 장치에서 확인합니다.

소프트웨어 검사와 컴파일은 하드웨어 실측을 대신하지 않습니다. 실제 모터, 레이저, 착용 상태에서의 작동은 보드 업로드 후 확인해야 합니다.


## 수동 출력 테스트가 동작하지 않을 때

- 테스트 결과는 ESP32 응답 이후 표시합니다. ‘명령 접수’는 실제 불빛·진동을 확인했다는 뜻이 아닙니다.
- 기기 설정 상단의 **분석·출력 대상**이 연결된 발인지 확인하세요. 오른발이 미등록이면 오른발 테스트는 실패합니다.
- **센서 점검 · 진동과 레이저 테스트**에서 DRV2605L 상태를 따로 확인할 수 있습니다. 인식 실패라면 모터 OUT+/OUT−뿐 아니라 드라이버 VIN·GND·SDA GPIO13·SCL GPIO14를 점검합니다.
- 현재 4-2는 BMI270과 DRV2605L을 공통 I²C 선에서 부팅 시 초기화합니다. TCA의 하위 채널에 연결하는 구성이 아닙니다. 전원을 끈 상태에서 배선을 확인한 뒤 다시 켜거나 EN/RESET을 누르세요.
- 레이저 명령은 접수되는데 빛이 없으면 레이저 정격 전원, 공통 GND, 베이스 저항과 트랜지스터 제품별 B·C·E 위치를 확인해야 합니다. 웹의 `laser=true`는 GPIO 출력 상태이며 광센서로 확인한 실제 발광 상태가 아닙니다.
- 개인 IMU 보정은 자동 FoG 출력에 필요합니다. 수동 진동·레이저 테스트 자체는 개인 보정 없이도 사용할 수 있습니다.
