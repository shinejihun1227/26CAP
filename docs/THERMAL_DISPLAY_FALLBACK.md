# 온습도 표시 보완

웹 히트맵 표시 기능입니다. 같은 발 안의 빈 칸 보완은 `two-shared` 프로필에 적용하며, 온습도가 모두 미수신인 발의 반대쪽 평균 참조는 2센서·4센서 프로필 모두 지원합니다. ESP32 재업로드나 서버 재시작 없이 웹 새로고침으로 적용됩니다.

| 같은 발의 실측 수신 | 화면 표시 |
| --- | --- |
| 2개 | T1·T3 실측 유지, T2·T4는 두 실측값의 평균으로 추정 |
| 1개 | 해당 실측 칸 유지, 나머지 세 칸은 수신된 한 값으로 추정 |
| 0개 · 발은 연결됨 · 반대쪽 유효 실측 있음 | 네 칸에 반대쪽 물리 센서의 실측 평균 표시 |
| 양발 모두 0개 또는 해당 발 연결 끊김 | 네 칸 모두 측정 대기 |

숫자 칸은 동일한 모양으로 표시하고, 실측 수신 개수와 추정 칸 개수는 히트맵 상단에 모아 안내합니다. 개별 값에 마우스를 올리면 실측·추정 출처를 확인할 수 있습니다. 평균에 온도 최대 ±0.15°C, 습도 최대 ±0.6%p의 위치별 고정 편차를 더합니다. 이 편차는 화면 표시용이며 센서 오차를 보정하거나 다른 부위의 실제 온습도를 예측한 값이 아닙니다. 습도는 0–100% 범위를 넘지 않습니다. 매번 무작위로 바뀌거나 과거 값을 이어 붙이지 않습니다.

평균은 유효하게 수신된 물리 센서만 사용하며 복제된 슬롯은 중복 평균하지 않습니다. 반대쪽 발을 참조할 때는 실측 평균을 그대로 사용하고 위치별 편차를 더하지 않습니다. 상단에 ‘왼발 평균 사용’ 또는 ‘오른발 평균 사용’, 요약에는 ‘참고 평균’을 표시합니다. 수신이 복구되면 해당 발의 실측값으로 즉시 돌아갑니다. 4개 독립 센서 프로필에서 일부 센서만 빠진 경우 해당 칸은 측정 대기로 유지합니다.

원본 상태와 readiness는 변경하지 않습니다. 실측 평균, 센서 연결 개수, 데이터 저장, 시계열 비교, AI·알림에는 추정값이 들어가지 않습니다. 좌우 차이는 양발 실측이 있을 때만 표시하며 복사된 평균으로 0을 만들지 않습니다. 기기 설정의 온습도 수신 표기도 실제 물리 센서 개수(예: 1/2)로 표시합니다.

이 기능은 누락된 화면 표시를 보완합니다. 센서 통신 끊김 자체를 수리하는 기능은 아닙니다.

검증: `node --test cap_web/tests/thermal-display.test.mjs cap_web/tests/pressure-four.test.mjs cap_web/tests/insole-hub.test.mjs cap_web/tests/observation-monitor.test.mjs`

화면 검증용 가상 데이터: `/tests/fixtures/thermal-display-preview.html` (실제 장치·기록 변경 없음).
