- 앞발 하중 규칙: 정지 보정값 대비 앞쪽 50% 이상·뒤꿈치 60% 미만이 **2초** 지속될 때 압력 보조 판단에 반영합니다. 실제 체중 비율이나 의료적 기준이 아닙니다.
- 개인 압력 기준: 유효 걸음 5개 이상인 앞/뒤 센서 중 걸음 간격의 변동계수(CV)가 더 낮은 센서를 선택합니다. 이 변경은 다음 개인 보정부터 적용됩니다.
- WROOM 펌웨어: `cue_level_supported`, 진동 강도 0–127과 레이저 분리 제어, 64Hz IMU에서 3회 발 구름 후보 감지 정보를 추가했습니다. PC의 기존 로직이 후보를 확인한 뒤 5초 동안 출력을 억제합니다. 진동 세기 입력은 숫자로만 받도록 검사를 보완했습니다.
- 주의 단계는 지원 펌웨어에서 약한 진동 30·레이저 끔, 강한 신호는 진동 70·레이저 켬입니다. 구형 펌웨어 호환과 명령 만료 1.5초는 유지합니다.

## 검증과 적용 범위

Python AI 테스트 59개와 웹 테스트 250개를 통과했습니다. 실제 RF/CNN 가중치 로드·합성 센서 HTTP 연동, 연속 4개 창과 중간 점수 하락 시 초기화, 실제 2초 압력 유지 조건, 규칙적인 센서 선택, 감지 중지·재개 및 기존 ROM·CoP 기능을 검사했습니다. 합성 입력 테스트는 실착용 정확도 검증이 아닙니다.

최종 PC 주소를 포함한 펌웨어도 양발 전체 빌드를 통과했습니다. ESP32 Dev Module 왼발: Flash 857,829 bytes, 정적 RAM 46,104 bytes. ESP32-WROOM-DA 오른발: Flash 859,133 bytes, 정적 RAM 46,104 bytes. 두 빌드 모두 저장된 최종 `config.h`와 일치함을 확인했습니다.

진행 중이던 양발 보정이 완료된 후 PC AI 서버만 재시작했습니다. 8787 직접 API 및 웹 8000·8001에서 새 아티팩트 ID `550173eba8eeed906f49e23cf4ab78bf83c76d1522b97aa921743cb5624fef18`가 동일하게 확인되었습니다. 확인 시 양발 장치 연결·개인 보정 모델 로드·유효 분석이 모두 준비 상태였습니다. 웹 수집 서버는 재시작하지 않았습니다.

새 약한 진동·발 구름 후보 기능은 지원 WROOM 펌웨어가 필요합니다. 확인 시 연결된 양발 보드가 이미 `cue_level_supported: true`, `tap_api_version: 1`을 보고했습니다. 이번 작업에서 보드에 직접 업로드하지는 않았습니다. 펌웨어 코드 전체의 일치 여부는 기능 지원 정보만으로 확정할 수 없습니다. 새 개인 압력 기준 선택 방식은 다음 양발 보정부터 적용됩니다.
