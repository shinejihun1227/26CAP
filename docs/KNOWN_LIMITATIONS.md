# 팀 인수인계 — 검증 전/미구현 항목

패키징은 전체 실기기 검증이나 임상 검증을 뜻하지 않습니다. 원본 동작 코드는 보존하고 실행 환경·파일 정리·문서를 보완했습니다.

1. **ESP32 AP가 안 보이는 문제 미해결**: 센서 초기화 → Wi-Fi 순서여서 초기화가 멈추면 AP 시작에 도달하지 않을 수 있습니다. 아직 로그로 원인을 확정하지 않았습니다. 115200에서 리셋 직후 로그를 수집하고 `StepOn 03_final`, 센서 요약, `AP SSID`, `HTTP API ready` 중 마지막 출력 지점을 전달하세요. `WiFi.softAP()` 성공 여부 확인도 코드에 없습니다.
2. **실제 센서/배선 확인**: 핀맵, 센서 준비 플래그, 전원, 업로드 대상 ESP32-C3, 부팅 상태를 확인해야 합니다. 이번 공유 작업에서 보드를 업로드하거나 진동/레이저를 동작시키지 않았습니다.
3. **AI 보정 파일 미포함**: 사용자/부착 위치마다 새로 수집합니다. 자동 CSV 녹화기는 없으며 브라우저 기준선이 Python 축 보정을 대신하지 않습니다.
4. **한 발/양발 구분**: 펌웨어는 `FOOT_SIDE="left"`, `bilateral_available=false`입니다. 브리지는 단일 IMU를 모델 내부 `R_raw_acc`/`R_raw_gyro` 키에 매핑합니다. 실제 착용 발/학습 데이터/보정 기준의 정합성과 양발 동시 입력은 별도 검증이 필요합니다.
5. **64 Hz는 목표**: HTTP 최신 스냅샷에는 누락/지터가 생길 수 있고 느린 센서 읽기도 루프를 지연시킬 수 있습니다. 프레임 간격/누락/처리 주기를 계측해야 합니다. AI 결과는 64회/초가 아니라 0.5초 간격 창 판정입니다.
6. **입력 품질/재연결**: 브리지는 일부 누락/비정상 수치를 0으로 치환하고 센서 준비 플래그를 완전한 입력 차단 조건으로 사용하지 않습니다. 큰 시간 간격에서 보간기는 초기화되지만 모델 창/상태까지 전부 초기화하지는 않습니다. 검증 전 안전 제어 판단에 사용하지 마세요.
7. **MediaPipe·보정 API**: 카메라 분석은 미연결이며 ESP32 `/api/calibrate`는 안내 응답입니다. 설정 화면이 있다고 관절 범위를 측정하는 것은 아닙니다.
8. **접근 범위**: 웹/AI/장치 API는 인증 없는 로컬 시연용이며 공개 인터넷용이 아닙니다. 기본 AP 암호는 공개 시연값입니다. 개인 데이터/실제 Wi-Fi 암호를 커밋하지 마세요.

팀원 테스트 순서: **웹 모의 데이터 → ESP32 ping/state → 실제 센서 표시(ai=0) → 보정 JSON → PC AI API → AI 웹 표시**. 앞 단계가 실패하면 뒤 단계 화면 문제로 판단하지 마세요.
