# 우리 센서 데이터 → CSV → AI 점수

2026-09-14 · `wongi` 연동

`run.bat` 실행 후 **http://127.0.0.1:8000/data/** 에서 사용합니다. 기존 웹의 AI 카드에도 **데이터 수집 · CSV 분석** 링크가 있습니다. 같은 PC에 접속한 휴대폰도 `/data/`를 사용할 수 있습니다.

## 1. 무엇을 수집하나요?

현재 ZIP의 RF/CNN 모델에는 **BMI270의 원시 6축 IMU**를 연결합니다. 가속도는 중력을 포함한 **g**, 각속도는 **°/s**, 시간은 **장치의 경과 시간**입니다. PC 수신 시각이나 웹 화면 갱신 주기를 샘플 시각으로 사용하지 않습니다. 가속도에 9.81을 곱하거나, 중력을 빼거나, 축을 임의로 바꾸거나, 미리 정규화하지 마세요.

한 파일에는 한 참가자·회차·발·장치·부팅·부착 위치만 넣습니다. 양발은 파일을 나누고 각 발의 보정 파일로 각각 분석합니다. 압력 4채널, 온습도, 카메라 관찰치는 기존 화면에서 따로 관찰하며 현재 모델 점수에 임의로 더하지 않습니다.

| 표준 CSV 열 | 내용 | 예 / 단위 |
|---|---|---|
| `timestamp_ms` | 실제 장치 경과 시각, 엄격히 증가 | 밀리초 |
| `raw_acc_x`, `raw_acc_y`, `raw_acc_z` | 원시 가속도 3축, 중력 포함 | g |
| `raw_gyro_x`, `raw_gyro_y`, `raw_gyro_z` | 원시 각속도 3축 | °/s |
| `device_id` | 고정된 장치 식별자 | 펌웨어의 device_id |
| `boot_id` | 부팅마다 달라지는 식별자 | 펌웨어의 boot_id |
| `side` | 좌우 발 | `left` / `right` |
| `participant_id` | 참가자 코드 | `P001` 등, 실명 불필요 |
| `session_id` | 이번 측정 회차 | `20260914_S01` 등 |
| `placement` | 센서 부착 위치 | `shoe`, `insole`, `ankle`, `shank` |
| `label` | 선택 수집 메모 | `walking`, `turning`, `unlabeled` 등 |

다운로드 양식: [`cap_web/data/imu-template.csv`](../cap_web/data/imu-template.csv). 헤더만 있으며 예시 센서값은 들어 있지 않습니다.

```csv
timestamp_ms,raw_acc_x,raw_acc_y,raw_acc_z,raw_gyro_x,raw_gyro_y,raw_gyro_z,device_id,boot_id,side,participant_id,session_id,placement,label
```

인코딩은 UTF-8(BOM 허용)입니다. 권장 수집률은 **64~100 Hz**, 허용 최소 평균은 **32 Hz**입니다. 파일당 **8 MiB / 60,001행 / 10분** 중 먼저 도달하는 한도를 적용합니다. 두 파일을 담은 JSON 요청의 한도는 20 MiB입니다.

## 2. 보정과 측정을 어떻게 하나요?

1. 참가자 코드·회차·발·부착 위치를 입력합니다. 센서를 고정하고 방향을 유지합니다.
2. **보정 파일**: 첫 5초 가만히 서기 → 이어서 20초 평소처럼 걷기, 총 25초를 기록합니다. 첫 25초로 중력축·보행축과 정규화 기준을 구합니다. 이후 추가 행은 정규화에 포함하지 않습니다.
3. 같은 착용 상태에서 **측정 파일**을 기록합니다. 권장 30~60초 이상이며, 최소 연속 4초가 있어야 모델 창을 만들 수 있습니다. 원하는 관찰 동작을 기록하고 메모를 남깁니다.
4. 두 CSV를 선택해 **데이터 검사**로 확인하거나 바로 **모델 분석 시작**을 누릅니다. 분석 시작 시에도 같은 검사를 반드시 수행합니다.
5. 결과의 **마지막 분석 창**, **가장 높은 상태의 창**과 시간별 CSV를 확인합니다. 두 카드가 가리키는 시간은 다를 수 있습니다.

착용자 또는 센서 부착이 바뀌면 보정부터 다시 기록합니다. 보정·측정 파일의 참가자, 회차, 발, 장치, 위치가 같아야 합니다. 각 파일 내부에서는 boot_id도 같아야 하며, 두 파일 사이의 재부팅은 장치와 착용 상태를 유지한 경우 허용합니다. 실제 부착 유지 여부는 수집자가 확인해야 합니다.

### 방법 A: 웹의 실제 STA 센서 기록

기존 기기 연결 화면에서 해당 발의 실제 IMU를 먼저 연결합니다. `/data/`에서 **보정 25초 기록** 또는 **측정 기록**을 누르면 3초 준비 후 서버가 실제 샘플 이력을 CSV에 기록합니다. 브라우저 화면 갱신 횟수를 데이터로 기록하지 않습니다.

- 화면이 첫 5초 정지와 이후 20초 보행을 안내합니다. 종료되면 CSV와 기록 정보를 내려받을 수 있습니다.
- **보정 파일로 연결 / 측정 파일로 연결** 버튼으로 방금 기록한 데이터를 업로드 영역에 바로 연결합니다.
- 측정 시간은 10~600초, 기본 60초이며 자동 종료됩니다. 일찍 끝내기도 가능합니다. 보정을 일찍 끝내면 실패로 표시합니다.
- 장치/부팅 변경, 100ms 초과 간격, 2초 이상 유효 샘플 미수신 시 중단 사유를 기록합니다. 실패한 원본은 내려받아 점검할 수 있지만 바로 분석에 연결하지 않습니다.
- 실시간 개인 보정이나 다른 CSV 수집과 동시에 같은 수집을 시작할 수 없습니다. CSV 모델 분석은 수집을 마친 뒤 진행합니다.
- 이 페이지의 보정은 CSV 분석 전용입니다. 기존 실시간 모델 보정 파일을 덮어쓰지 않습니다. 실시간 판단용 보정은 기존 AI 카드에서 진행합니다.

### 방법 B: 기존 ESP32-WROOM USB CSV

기존 [`06_bmi270_csv_wroom`](../firmware/stepon_c3/06_bmi270_csv_wroom/README.md) 수집기를 그대로 지원합니다. 해당 폴더에서 실행합니다. `COM7`은 예시입니다.

```powershell
.\record.bat --list-ports
.\record.bat --port COM7 --seconds 25 --label calibration --side left --placement shoe
.\record.bat --port COM7 --seconds 60 --label walking --side left --placement shoe
```

첫 명령은 **첫 유효 샘플부터** 5초 정지 + 20초 보행을 진행해야 합니다. USB 수집기에는 웹 기록의 3초 준비 시간이 없습니다. 별도의 타이머/수집 진행 시간으로 동작을 맞춥니다. 각 명령이 끝난 뒤 생기는 `recordings/gait_*.csv` 두 개를 사용합니다. 같은 이름의 JSON 파일은 수집 품질 기록이며 업로드 필수 파일은 아닙니다.

| USB CSV의 열 | 자동 변환 |
|---|---|
| `device_time_us` | 1,000으로 나눠 `timestamp_ms` |
| `ax_g`, `ay_g`, `az_g` | `raw_acc_x`, `raw_acc_y`, `raw_acc_z` |
| `gx_dps`, `gy_dps`, `gz_dps` | `raw_gyro_x`, `raw_gyro_y`, `raw_gyro_z` |
| `device_id`, `boot_id`, `side`, `placement`, `label` | 의미를 유지하여 연결 |
| `sequence`, `read_errors`, `tx_drops`, `gap_events`, `clip_mask` | 누락·카운터·포화 검사 |

USB CSV에 없는 참가자 코드/회차는 웹 입력값으로 붙입니다. `side`와 `placement`가 비어 있거나 `unknown`이면 웹에서 실제 값을 지정합니다. 파일에 명시된 값이 웹 입력과 다르면 실패합니다. `host_utc`와 `host_elapsed_s`는 원본에 보존하지만 모델 시간축에는 사용하지 않습니다.

이 PC에 이미 있던 2026-09-12 수집 파일은 메타데이터상 **644행, 6.471초, 약 99.37 Hz**, `side=unknown`, `placement=unknown`입니다. 이 파일만으로 참가자별 보정값을 만들거나 점수를 검증하지 않았습니다. 실제 발/부착 위치와 같은 착용 상태의 25초 보정 기록이 필요합니다. 원본은 Git에 포함하지 않습니다.

## 3. 내부 연결과 최종 점수

```text
USB 원본 CSV 또는 실제 STA 샘플 기록
  → UTF-8 / 열 / 유한 수치 / 단위 범위 / 장치·회차 / 시간 검증
  → 보정 CSV의 5초 정지·20초 보행 검증
  → 보정축과 정규화 기준 생성
  → 장치 시각을 기준으로 64 Hz 재샘플링
  → 256샘플(4초) 창, 32샘플(0.5초) 간격
  → ZIP의 RF + CNN → 원래 모델 점수 → 기존 상태 머신/움직임 조건
  → 판정 점수(0~100), normal / warning / confirmed, 근거
```

100ms를 넘는 누락은 긴 구간을 보간하지 않습니다. 측정 CSV에서는 이전 시간 이력과 판정을 초기화하고 새 4초 창부터 재개합니다. 보정 CSV에서는 누락을 오류로 처리합니다. 장치 시각 중복/역행, 파일 내부 장치·부팅 혼합, 비수치·NaN·무한대, 센서 범위 초과, USB 센서 포화, 보정의 정지 실패·움직임 부족·낮은 축 신뢰도는 분석을 막습니다.

CSV 분석은 별도 Python 프로세스의 독립 모델 상태로 수행합니다. 실제 모델 파일은 교체된 ZIP의 가중치를 그대로 사용합니다. 입력값으로부터 추론하는 과정이며 **모델 재학습이 아닙니다**. 개인 보정은 축과 정규화 기준을 맞추는 과정입니다.

## 4. 어떤 결과가 나오나요?

- `windows.csv`: 각 창의 장치 종료/시작 시각, 경과 시간, 구간 번호, RF 점수, CNN 점수, 원래 모델 점수, 판정 점수, 100점 환산값, 상태, 근거, 해당 시각의 수집자 메모.
- `result.json`: 전체 창 결과, 상태별 창 개수, 마지막/최고 상태의 창, 수집 품질, 입력 메타데이터, 모델·보정 SHA-256 식별자.
- `measurement.csv`, `calibration.csv`: 단위를 유지하고 열 이름을 통일한 표준 CSV.
- `calibration.json`: 이 작업의 축·정규화 보정값.
- `manifest.json`: 입력 원본의 해시와 품질, 참가자/회차, 진행·완료/실패 정보.

파일 전체의 단일 점수로 평균내지 않습니다. 겹치는 4초 창의 개수는 보행동결 사건 수나 지속 시간과 같지 않습니다. 정확한 관찰 구간은 시간별 결과로 확인합니다. `label`은 모델 입력이나 임상 정답이 아니며 자동으로 정확도를 계산하지 않습니다. 성능 평가/재학습에는 별도로 검증된 보행동결 정답 시작·끝 시각 및 참가자 단위로 나눈 학습/평가 데이터가 필요합니다.

기록과 결과는 **`.stepon-data/ai/datasets/<작업 UUID>/`**에 보존됩니다. 원본 두 파일도 서버 내부에 남으며 정해진 다운로드 파일만 노출합니다. Git에는 원본·개인 정보·생성 보정·분석 결과를 포함하지 않습니다. 서버 재시작 시 완료된 결과는 다시 열 수 있고 진행 중이던 미완료 기록은 중단으로 표시합니다. 최근 목록은 20개이며 이전 작업도 파일로 보존됩니다.

## 5. API / CLI

모든 웹 요청은 같은 출처의 Node `/api/ai` 프록시를 거쳐 로컬 Python으로 전달합니다.

| 메서드 / 경로 | 동작 |
|---|---|
| `GET /api/ai/datasets` | 최근 20개 작업과 진행 중 작업 ID |
| `POST /api/ai/datasets/validate` | CSV 두 파일의 형식·품질·보정 검사 |
| `POST /api/ai/datasets/analyze` | 검사 후 202 + 분석 작업 ID 반환 |
| `GET /api/ai/datasets/<id>` | 진행률·실패 사유·완료 결과 요약 |
| `GET /api/ai/datasets/<id>/windows.csv` 등 | 정해진 결과 다운로드 |
| `POST /api/ai/datasets/record/start` | 실제 센서 CSV 수집 시작 |
| `POST /api/ai/datasets/record/stop` | `{ "id": "작업 ID" }`로 수집 종료 |

분석/검사 요청의 JSON 필드는 `participant_id`, `session_id`, `side`, `placement`, `calibration_csv`, `measurement_csv`입니다. 두 CSV 필드는 파일 내용 문자열입니다. 경로나 모델 파일을 클라이언트가 지정하지 않습니다. 수집 시작은 메타데이터 네 필드와 `purpose`(`calibration`/`measurement`), 선택 `duration_s`를 받습니다.

기존 보정 JSON이 있는 경우 CLI도 동일한 CSV 변환/실시간 추론 경로를 사용합니다.

```powershell
.\.venv-ai\Scripts\python.exe web\ai_bridge\analyze_csv.py measurement.csv --calibration left.calibration.json --foot left --out result.json
```

구형 7열 CSV CLI 호환용으로만 장치 메타데이터 생략과 명시적 `--fs`를 지원합니다. 새 웹 업로드에서는 장치 시간과 장치/부팅 ID가 필수입니다.
