# 현재 코드 기준 알고리즘

## PC FoG AI — IMU의 보행동결 유사 패턴

목적은 동결과 유사한 패턴 관찰입니다. 질환 확진이나 치료 효과 판정이 아닙니다.

1. 가속도(g)/자이로(deg/s)와 프레임·시각을 HTTP로 수집합니다.
2. 실제 시각 사이를 선형 보간해 64 Hz 시간축을 구성합니다. 요청 주기와 신규 센서 샘플링률은 별개입니다.
3. 보정 JSON으로 가속도 축을 수직/전후/좌우로 재배열하고 사용자 기준으로 정규화합니다.
4. 256개 샘플(4초)을 모아 32개(0.5초)마다 판정합니다.
5. RF는 FI, 3축 표준편차, SMA, 주파수 특징 6개를 사용합니다. FI는 수직 가속도 3~8 Hz와 0.5~3 Hz 대역 파워 비율입니다.
6. CNN은 정규화된 3축 시계열을 작은 1D 합성곱 네트워크(16/32/64 채널)에 넣어 walk/stop/fog 확률을 계산합니다.
7. 기본 ensemble은 RF/CNN 확률을 평균합니다. RF는 실시간 호출에서 `n_jobs=1`을 사용합니다.
8. 보정에서 yaw 축이 확인되면 창 내 자이로 최대-최소 차이가 250 deg/s를 넘을 때 FoG 점수를 억제합니다.
9. ensemble 진입은 0.39/2회 연속, 이탈은 0.24입니다. 이후 motion gate가 `normal`/`warning`/`confirmed` 등급을 결정합니다.

`deploy_config.json`이 실제 배포 설정입니다. `last_fog_score`는 yaw 억제 **이전** 점수여서 높은 점수와 최종 `normal`이 동시에 나올 수 있습니다. `confirmed`는 출력 등급 이름이지 의료적 확진이 아닙니다.

코드와 메타데이터는 Daphnet/FoG-STAR 환자 IMU와 HuGaDB 일반 보행/정지 데이터를 사용하는 학습 파이프라인을 설명합니다. 원본 데이터와 실험 전체는 없어 기존 평가 수치를 이번에 재현했다고 주장하지 않습니다. 압력·온습도·카메라 랜드마크는 현재 RF/CNN 입력이 아닙니다.

## 웹 발 디딤·재활 규칙 — AI와 별도

`cap_web/src/data/gait-algorithms.js`에서 압력을 전족/중족/후족·내측/외측으로 묶어 비율, 압력 중심의 상대 위치, 접촉 여부를 계산합니다. IMU로 움직임/충격의 대리 지표도 계산합니다.

사용자 기준선/허용 범위로 하중·디딤 편차를 관찰하고 최근 관측 창의 반복 조건과 쿨다운을 적용합니다. 양발 비교에는 실제 양발 데이터가 필요합니다. 압력 0~100은 ADC 변환값이며 하중계 보정 없이는 kg/N이 아닙니다. 관절 각도나 실제 발 높이를 직접 측정하는 것도 아닙니다.

압력 지도에서 50 이상을 밝게 표시하는 시각 기준과 접촉 판정 `contactThreshold=16`은 다른 설정입니다.

## 온습도 규칙

SHTC3의 뒤꿈치/중앙/앞꿈치/발가락 온습도를 표시합니다. 양발의 같은 부위 값이 있으면 온도 차이의 평균/최대 및 습도 차이로 관찰 상태를 정합니다. 질환·궤양을 AI가 진단하는 기능이 아닙니다. 한쪽 값이 없으면 실제 좌우 차이는 계산할 수 없습니다.

## ESP32 규칙과 출력

`fogCandidate()`는 압력 합계와 자이로 크기 임계값을 비교하는 단순 후보 규칙입니다. PC RF/CNN과 다릅니다. 자동 큐/레이저는 기본 꺼져 있습니다. 웹의 수동 출력·재활 피드백 경로와 PC AI 결과 API는 별개이며, AI 브리지에서 진동·레이저 자동 명령을 보내지는 않습니다.

## MediaPipe 개인화

현재는 키·다리 길이·주 사용 발 등의 설정 화면과 브라우저 저장 기능입니다. 카메라 획득, MediaPipe 모델 로드, 랜드마크/관절 ROM 계산, 재활 기준 반영의 전체 연결은 후속 작업입니다. FoG와 분리된 개인화 기능으로 개발할 수 있지만 완료된 AI 기능으로 소개하면 안 됩니다.
