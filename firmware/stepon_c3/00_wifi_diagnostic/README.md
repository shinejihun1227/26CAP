# ESP32-C3 USB / Wi-Fi 전용 진단

`03_final`과 별개인 임시 진단 스케치입니다. 보드에 올리면 실제 센서 펌웨어를 대신 실행합니다. `03_final` 원본은 수정하지 않습니다.

## 확인 방법

1. Arduino IDE에서 이 폴더의 `00_wifi_diagnostic.ino`를 엽니다.
2. `ESP32C3 Dev Module`, `USB CDC On Boot: Enabled`, 실제 연결된 COM 포트를 선택합니다. 시리얼 모니터는 115200 baud입니다.
3. 업로드 후 `StepOn-C3-DIAG`를 검색합니다. 비밀번호는 `stepon1234`입니다. 인터넷 없음 표시는 정상입니다.
4. 해당 Wi-Fi 연결 후 `http://192.168.4.1/api/ping` 또는 `/api/diag`를 엽니다. 진단 JSON이 나오면 무선 연결 및 HTTP 왕복까지 확인한 것입니다.
5. 시리얼에서는 2초마다 AP 상태, 가동 시간, 연결 수, 여유 메모리 등이 출력됩니다. 모니터를 늦게 열어도 상태를 볼 수 있습니다.

## 진단 범위와 안전

- I2C·압력·온습도·IMU·AI 처리를 하지 않습니다. 진동 명령을 전송하지 않으며 기존 레이저 GPIO10은 LOW로 유지합니다.
- `/api/state`는 의도적으로 HTTP 503을 반환합니다. 진단값을 웹의 실제 센서값으로 오인하지 않도록 했습니다.
- AP 채널 1, WPA2 비밀번호, 최대 연결 4개를 사용합니다. Wi-Fi 저장 설정(NVS)은 지우지 않습니다. 출력 세기와 절전 설정을 임의로 변경하지 않습니다.
- `softap_call_ok`, `ap_running`, `ap_starts/ap_stops`, 실제 채널, `*_error`를 함께 봅니다. `ok=true`도 외부에서 전파가 수신된다는 보장은 아닙니다. 무선 검색과 HTTP 요청으로 별도 확인해야 합니다.
- 센서 코드를 제외했을 뿐, 실제 센서 배선과 전력 소모가 제거되는 것은 아닙니다. 전원 전압이나 RF 회로 품질을 측정하는 테스트도 아닙니다.
- USB 포트를 열거나 닫을 때 보드/드라이버에 따라 리셋될 수 있습니다. 진단 중 관측한 리셋을 곧바로 전원 불량으로 판단하지 않습니다.

## 원래 기능으로 복원

`../03_final/03_final.ino`를 Arduino IDE에서 열고 같은 보드와 USB CDC 설정으로 다시 업로드합니다. 해당 폴더의 `sensor_core.h`, `sensor_core_local.h`도 그대로 두세요. 복원 후 SSID는 `StepOn-C3`이고 센서 API는 `/api/state`입니다.

전체 플래시 삭제나 NVS 초기화는 이 진단에 필요하지 않습니다.
