# 4개 압력 + 4개 온습도 센서 적용 안내

## 한쪽 깔창의 연결 순서

| 웹 표시 / JSON 순서 | 부착 위치 | CD74HC4067 채널 |
|---|---|---|
| P1 / pressure[0] | 앞쪽 | C0 |
| P2 / pressure[1] | 가운데 안쪽 | C2 |
| P3 / pressure[2] | 가운데 바깥쪽 | C4 |
| P4 / pressure[3] | 뒤꿈치 | C6 |

가운데 두 개는 안쪽/바깥쪽으로 가정했습니다. P2·P3의 실제 부착 방향을 이 표와 맞춰야 내측·외측 비중이 맞습니다. 화면은 양발을 표시하지만 한 개 ESP32가 보내는 한쪽 깔창은 압력 4개, 온습도 4개입니다. 반대쪽 값은 복제하지 않습니다.

| 웹 표시 / JSON 순서 | 기존 온습도 부위 이름 | TCA9548A 채널 |
|---|---|---|
| T1 / temperature[0], humidity[0] | 뒤꿈치 | CH3 |
| T2 / temperature[1], humidity[1] | 발바닥 중앙 | CH4 |
| T3 / temperature[2], humidity[2] | 앞꿈치 | CH5 |
| T4 / temperature[3], humidity[3] | 발가락 | CH6 |

온습도 부착 부위를 새로 지정하지 않았으므로 기존 순서를 유지했습니다. MUX 채널 번호는 ESP32 GPIO 번호와 다릅니다. 보드 핀맵, I²C 주소 검색, MUX 전환 후 ADC 안정화 처리는 기존 그대로입니다. BMI270/DRV2605는 상위 I²C 버스에 연결합니다.

## 수정된 파일

- 펌웨어: `../firmware/stepon_c3/01_sensor_test/sensor_core.h`, `02_wifi_api/sensor_core_local.h`, `03_final/sensor_core_local.h`.
- 최종 규칙: `../firmware/stepon_c3/03_final/03_final.ino`의 압력 합계 기반 임계값을 같은 센서당 평균 기준으로 환산했습니다. 재배치 후 실측 보정은 별도 필요합니다.
- 웹 공통 매핑: `src/data/sensor-config.js` — 개수, 채널, 이름, 기본 표시 좌표, 계산용 상대 좌표.
- API 해석: `src/services/esp32-api.js` — 정확히 4개 데이터만 채택. 예전 8개나 잘못된 채널 정보는 측정 대기와 안내로 표시.
- 히트맵: `src/components/bilateral-heatmap.js` — 센서당 상대 압력 50% 이상 밝게, 미만 어둡게, 미측정은 `--`. 임계값은 `PRESSURE_ACTIVE_THRESHOLD`.
- 재활 지표: `src/data/gait-algorithms.js` — 앞쪽=P1, 가운데=P2+P3, 뒤꿈치=P4, 내측=P2, 외측=P3. 상대 압력은 4개 평균이며 CoP는 네 점의 가중 평균 추정입니다.
- 편집기·모바일·기기 안내 및 변화 추이도 같은 4개 계약을 사용합니다. 압력 표시 좌표 편집은 화면만 바꾸며 실제 채널 순서나 계산용 좌표를 바꾸지 않습니다.

8개 배치로 저장한 화면 좌표는 압력 부분만 새 4점 기본값으로 표시합니다. 기존 온습도 좌표와 다른 편집 내용은 유지합니다. 이전 압력 기준선은 재사용하지 않으며 `개인 기준선`을 다시 생성해야 합니다. 과거 추이 기록은 삭제하지 않고 새 알고리즘/배치 식별자로 비교 그룹을 분리합니다. 관절 카메라 기록에는 영향을 주지 않습니다.

압력 4개만으로 실제 체중, 정밀 족저압 분포, 치료 효과를 확정할 수 없습니다. RF/CNN FoG 모델의 가속도·자이로 입력과 MediaPipe 각도 분석은 이번 변경으로 수정하거나 재학습하지 않았습니다.

## 실제 확인 순서

1. 센서 단독 확인은 `01_sensor_test.ino`, Wi-Fi 확인은 `02_wifi_api.ino`, 최종 사용은 `03_final.ino`를 Arduino IDE에서 엽니다. 각 스케치 폴더의 `.h` 파일도 함께 있어야 합니다.
2. 사용할 스케치를 컴파일하고 ESP32-C3에 업로드합니다. 이 코드 수정 작업에서는 장치에 업로드하거나 출력 장치를 작동시키지 않습니다.
3. AP 설정을 유지했다면 노트북을 `StepOn-C3`에 연결하고 `http://192.168.4.1/api/state`에서 `pressure_count: 4`, `pressure_channels: [0,2,4,6]`, `pressure` 길이 4, `shtc3_channels: [3,4,5,6]`을 확인합니다.
4. P1→P4를 하나씩 눌러 해당 배열 칸과 웹 센서 점만 반응하는지 확인합니다. 각 압력 채널의 독립 풀다운 저항/배선도 확인하세요.
5. 로컬 서버 8000·8001을 실행하고 브라우저에서 Ctrl+F5로 새로고침합니다. 실제 센서 화면은 `http://127.0.0.1:8000/?esp32=1&ai=0&view=live&esp32Url=http%3A%2F%2F192.168.4.1&mobile=0`입니다. 8001은 편집 미리보기입니다.
6. 온습도 모드에서 T1~T4를 확인합니다. 미응답 센서는 `--`이며 0으로 간주하지 않습니다.
7. 새 배치의 개인 기준선을 다시 생성한 뒤 재활 지표를 관찰합니다. 변화 추이 저장 시 동일한 측정 조건 코드를 사용하세요.

2번 스케치는 기존 목표 20 Hz Wi-Fi 테스트, 3번은 기존 64 Hz 센서 프레임 목표를 유지합니다. 웹 새로고침/통신 주기와 센서 샘플링 주기는 별개입니다.

## 자동 검사

`cap_web`에서 `node --test tests/*.test.mjs`를 실행합니다. 4채널 변환, 잘못된 8채널 데이터 차단, 임계값, 좌우 표시, 이전 기준선/기록 분리, 펌웨어 채널 일치를 검사합니다. 실제 하드웨어 배선·ADC 특성·센서 정확도는 자동 검사로 확인하지 못합니다.
