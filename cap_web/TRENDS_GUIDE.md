# 개인 변화 추이 사용 안내

센서 배치는 2026-09-09부터 압력 4개(C0·2·4·6)·온습도 4개(CH3·4·5·6)입니다. 새 압력 지표는 `web-rehab-rules-pressure4-v2`와 `stepon-pressure-4-v1` 식별자로 저장됩니다. 이전 8개 배치의 일별 기록은 유지하되 별도 비교 조건으로 표시하여 서로 평균내지 않습니다. 압력 개인 기준선도 다시 생성하세요.

## 어디에서 확인하나요?

- 실제 기록·비교: `http://127.0.0.1:8000/?view=trends&preview=1&mobile=0`
- 화면 편집: `http://127.0.0.1:8001/?mode=editor&screen=trends`
- 왼쪽 메뉴 또는 모바일 메뉴의 **변화 추이**를 선택합니다. 8001은 편집용으로 실제 기록을 시작하지 않습니다.

## 매일 사용하는 순서

1. **관절 기록**: MediaPipe에서 같은 측정 코드(예: P01), 카메라 환경·자세·방향·관절을 선택합니다. 15초 측정을 끝내고 **기록 저장**을 누릅니다. 정면·좌측·우측은 한 세트로 묶을 수 있지만 서로 다른 각도를 평균 내지는 않습니다.
2. **센서 기록**: ESP32 Wi-Fi를 연결하고 기존 센서 모드(`esp32=1`, AI 브리지도 쓸 때 `ai=1`)로 웹을 엽니다. 변화 추이에서 같은 측정 코드와 센서 환경 코드를 입력한 뒤 저장 동의 → **센서 기록 시작**을 누릅니다. 시연 모드에서는 시작할 수 없습니다. 이 기능은 ESP32 출력이나 FoG 모델 학습을 변경하지 않습니다.
3. **비교**: 기준 날짜를 선택한 뒤 **전날 / 직전 기록일 / 이전 7일 평균** 중 선택합니다. 날짜별 표에서도 날짜를 선택할 수 있습니다. 관절·센서 조건이 여러 개라면 비교할 조건을 선택합니다.
4. **요약**: 선택한 관절 범위와 선택한 센서 조건의 각 지표를 비교합니다. 관절 범위 감소, FoG·규칙 경고 표본 비율 증가 등은 다시 확인할 수치 변화로 설명하지만 악화로 확정하지 않습니다.
5. **보관**: 필요할 때 **내 기록 JSON**으로 현재 측정 코드의 관절 원본·3방향 세트·센서 일별 요약을 함께 내보냅니다. 센서 날짜별 기록은 하단 기록 관리에서 개별 삭제할 수 있습니다. 관절 기록 삭제는 MediaPipe에서 합니다.

## 계산 방법과 비교 제한

| 구분 | 저장·비교 방식 |
| --- | --- |
| 날짜 | 한국 시간 Asia/Seoul, 자정 기준 |
| 관절 | 기존 품질 기준을 통과한 15초 기록의 P95−P05 관찰 범위; 같은 날짜의 여러 기록은 중앙값 |
| 전날 | 정확히 하루 전. 기록이 없으면 비교 대기 |
| 직전 기록일 | 선택 날짜보다 이전인 유효 기록 중 가장 최근 날짜 |
| 이전 7일 | 선택 날짜를 제외한 이전 7일의 유효 일별 관찰값 평균. 날짜별 동일 가중치; 누락일은 0으로 채우지 않음 |
| 센서 | 보이는 변화 추이 탭에서 약 1초마다 최신 센서 프레임 1개를 관찰·저장; 같은 사람·설정·초의 중복 표본 제외 |
| 센서 일별 값 | 지표별 유효 표본의 평균. 지표마다 분모를 별도로 저장. 10표본 미만은 비교하지 않음 |
| 실시간 요약 | 서버 저장 기록을 약 5초마다 다시 읽음. 웹/탭이 닫혀 있을 때 계속 수집하는 백그라운드 서비스는 아님 |

센서 탭은 64Hz 원시 데이터 녹화기가 아닙니다. FoG AI의 기존 64Hz 입력·4초 창·0.5초 간격 분석은 기존 AI 브리지에서 수행하고, 이 탭은 그 최신 결과와 웹 규칙의 관찰값을 약 1Hz로 요약합니다.

### 각 지표가 뜻하는 것

- **AI FoG 판정 표본 비율**: 모델과 장치가 준비되고 최신 추론 결과가 있을 때만 `confirmed` 상태를 100, `normal/warning`을 0으로 표본화한 비율입니다. 발병 확률, 총 발생 횟수 또는 정확한 동결 지속 시간은 아닙니다. AI 브리지 미연결·워밍업·오래된 결과는 0이 아니라 미측정입니다.
- **좌우 하중 비율 차이**: 실제 양발 압력이 있을 때만 계산합니다. 한쪽 깔창으로 양발 균형을 만들어내지 않습니다.
- **상대 압력·뒤꿈치·앞꿈치·외측 비중**: 현재 알고리즘의 상대 압력 및 압력 분포 관찰값입니다. kg, 임상 착지 성공률, 실제 추진력이 아닙니다.
- **재활 규칙 경고 표본 비율**: 개인 보정과 IMU·압력 입력이 준비된 경우 기존 규칙 경고가 나타난 표본의 비율입니다. 알림 발생 횟수가 아닙니다. FoG 우선 경고는 이 비율에서 제외합니다.
- **온도·습도**: 활성 발의 유효 SHTC3 채널 평균입니다. 같은 채널 구성끼리 비교하며 몸의 체온이나 질환을 판정하지 않습니다.

관절은 측정 코드·좌우·관절·자세·카메라 환경·신뢰도·모델 버전·영상 비율을 분리합니다. 센서는 환경 코드·활성 발·장치·양발 여부·온습도 채널·재활 설정/보정·AI 설정이 바뀌면 별도 조건으로 저장합니다. **신발·센서 위치·운동 종류·모델 가중치나 보정 파일을 바꾸면 반드시 새 환경 코드를 쓰세요. 모델 이름만으로 가중치 파일 변경을 자동 식별하지는 않습니다.**

오늘은 아직 진행 중인 기록입니다. 표본 수와 기록 시간대, 활동 종류가 다르면 수치가 달라질 수 있습니다. 이전 날짜보다 수치가 낮거나 높다는 사실만으로 임상적 개선·악화, 재활 효과를 확정할 수 없습니다. 별도의 검증된 종합 건강 점수를 만들지 않습니다.

## 실제 데이터 저장 위치

- 관절: 프로젝트 루트의 `.stepon-data/mediapipe/` (기존 저장소)
- 센서: 프로젝트 루트의 `.stepon-data/trends/daily-<해시>.json`
- 두 저장소 모두 웹 공개 폴더 밖이며 8000·8001이 공유합니다. `/api/rom`, `/api/trends`는 localhost와 같은 Origin만 허용합니다. 이름 대신 측정 코드를 쓰지만 로그인·사용자별 접근 제어·디스크 암호화는 구현되어 있지 않습니다.
- 카메라 영상·음성·원시 랜드마크·AI 보정 파일 경로는 새 센서 저장소에 넣지 않습니다. 센서는 날짜별 지표 합계·개수·최소/최대·시간·조건 및 중복 방지용 초 단위 시각만 보관합니다.
- 관절: 저장일부터 30일, 최대 300개 움직임/100개 참조값/30개 세트. 세트당 최대 30개 원본 연결.
- 센서: 한국 날짜 기준 최근 30일, 전체 최대 3,000개 날짜·사람·설정 묶음. 기간 만료 기록은 다음 저장소 접근 시 삭제합니다.
- 영구 삭제는 복구할 수 없습니다. 내보낸 JSON은 자동 삭제되지 않으므로 별도 관리하세요.
- 기존 `stepon-rehab-daily-log` 브라우저 임시 기록은 측정 코드와 시연 여부가 없어 개인 비교 자료로 자동 이전하지 않습니다. 기존 보행 리포트의 고정 82점/+6.8% 개선율은 제거했습니다.

## 유지보수 및 검증

| 파일 | 역할 |
| --- | --- |

| `tests/trends.test.mjs` | 합성 데이터로 날짜·분리·저장·보안·화면 문구 검증 |

서버를 재시작한 뒤 브라우저를 새로고침해야 새 API와 화면을 사용합니다. 잠금 오류가 반복되면 다른 창의 기록을 중지하고 두 웹 서버를 모두 종료한 다음 `.stepon-data/trends/.trend-write.lock`의 잔류 여부를 확인하세요. 서버가 실행 중일 때 잠금을 삭제하지 마세요.

프로젝트 루트에서 `node --test cap_web/tests/*.test.mjs`로 검증합니다. 테스트는 별도 임시 폴더만 사용하며 실제 개인 기록·카메라·센서 출력을 조작하지 않습니다. 실제 인체 인식 정확도나 치료 효과에 대한 검증은 아닙니다.
