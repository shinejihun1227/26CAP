# StepOn 웹캠 관절 움직임 기록

## 사용자 코드와 관절 선택 (2026-09-09 갱신)

`사용자 코드 (측정 코드)`는 사람별 기록을 구분하는 이름표입니다. 프로그램 소스 코드나 검사·진단 번호가 아닙니다. 예를 들어 본인=P01, 팀원=P02로 정하고 **같은 사람은 날짜·관절·방향이 바뀌어도 같은 코드**를 사용합니다. 실명은 필요하지 않습니다. 로그인 기능이 아니므로 같은 PC를 쓰는 사람은 다른 코드의 기록도 볼 수 있습니다.

이전 화면은 정면에 어깨 벌림만 보이고 측면 선택 시 무릎·발목·팔꿈치·몸통–허벅지가 나타났습니다. 이제 **5개 부위, 좌우 총 12개 관찰 항목을 한 목록에 항상 표시**합니다. 관절 선택 시 필요한 촬영 방향이 자동 선택되지만, 실제 몸의 방향은 사용자가 바꾸고 방향 확인란을 체크해야 합니다. 좌측면↔우측면만 바꾸면 가능한 경우 같은 관절의 반대쪽으로 바뀝니다.

| 부위 | 동작 / 관찰값 | 촬영 방향 | 주의 |
|---|---|---|---|
| 어깨 | 옆 벌림 | 정면 | 팔꿈치–어깨–골반 투영 각도, 몸통 기울임 포함 가능 |
| 어깨 | 앞쪽 들기 **추가** | 해당 쪽 측면 | 위팔–몸통 투영 각도. 앞/뒤 움직임을 자동 구분하지 않으므로 몸 앞쪽 움직임으로 조건을 맞춤 |
| 팔꿈치 | 굽힘·펴기 | 해당 쪽 측면 | 어깨–팔꿈치–손목. 팔뚝 회전·과신전은 평가하지 않음 |
| 무릎 | 굽힘·펴기 | 해당 쪽 측면 | 골반–무릎–발목. 무릎 회전·과신전은 평가하지 않음 |
| 발목 | 정강이–발 상대각 | 해당 쪽 측면 | 무릎·발목·뒤꿈치·발끝 필요. 작은 발 선분의 가림/해상도에 민감하며 임상 배굴/저굴값과 다름 |
| 고관절 주변 | 몸통–허벅지 상대 굽힘 | 해당 쪽 측면 | 골반/허리 움직임이 섞여 독립 고관절 ROM이 아님 |

각 항목의 촬영 방법·각도 정의·한계를 선택창 아래에 표시합니다. 손목·손가락·목 회전·어깨 안팎 회전은 이번 버전에 추가하지 않았습니다. 별도 랜드마크 모델/촬영 절차/참조 장비 검증이 필요한 작업이며, 현재 Pose 기반 선택 목록에 억지로 포함하지 않습니다.

새 어깨 앞쪽 들기 ID는 `left_shoulder_flexion`, `right_shoulder_flexion`입니다. 기존 `left_shoulder`/`right_shoulder`는 정면 벌림 의미와 수식을 유지합니다. 기존 기록·기준선을 삭제하거나 새 동작으로 바꾸지 않고, 새 동작의 기준선은 따로 지정합니다. 방향별 세트, JSON/CSV 내보내기, 개인 변화 추이도 새 ID로 동작합니다. 서버 `/api/rom`의 `metricIds`에서 12개 지원 항목을 확인할 수 있습니다.

화면이 열려 있었다면 기록을 먼저 저장/중단하고 Ctrl+F5로 새로고침하세요. 추가 관절 저장에는 새 서버 코드가 필요하므로 기존 8000·8001 서버를 종료한 후 다시 실행해야 합니다. 이 PC에서는 구현 후 해당 서버를 재시작합니다.

수정 위치: `src/mediapipe/rom-math.js`(각도 정의), `src/mediapipe/rom-joints.js`(전체 관절 목록·방향 전환·촬영 가이드), `src/mediapipe/rom-controller.js`(선택 반영), `src/views/mediapipe-view.js` 및 `src/styles/mediapipe-rom.css`(화면).

### 치료 목적 활용의 경계와 참고 근거

치료 중 담당 전문가와 정한 동작을 같은 조건에서 반복 기록하는 보조 관찰 도구입니다. 정상 범위·목표 각도·운동 강도를 자동 처방하지 않으며, 통증 시 멈춰야 합니다. P95−P05는 촬영 중 관찰 범위이지 최대 능동/수동 관절가동범위의 임상 검사 결과가 아닙니다. `외부 각도계와 오차 확인`으로 같은 각도 정의/자세의 참조값을 비교하세요. 본 앱의 정확도나 치료 효과를 검증한 임상시험은 없습니다.

- [Google MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker): 모델이 추정하는 33개 신체 위치의 정의. 모델 지원 부위가 곧 해당 관절 ROM의 임상 정확도 보증은 아닙니다.
- [Latreche et al., 2023, Measurement](https://doi.org/10.1016/j.measurement.2023.112826): MediaPipe 어깨 움직임을 각도계 등과 비교한 연구. 연구 시스템과 이 앱은 같지 않습니다.
- [Feasibility of 3D Body Tracking from Monocular 2D Video Feeds in Musculoskeletal Telerehabilitation](https://pmc.ncbi.nlm.nih.gov/articles/PMC10781343/): 운동 자세·가림·깊이 모호성 등 제한을 보고한 연구. 다른 처리 방식의 성능 수치를 이 앱에 대입하지 않습니다.

## 무엇을 구현했나

노트북 웹캠에서 MediaPipe Pose Landmarker로 관절 위치를 추정하고, **정면·좌측면·우측면별 각도 변화와 개인 기준선**을 기록한다. 기존 ESP32 센서 → PC RF/CNN FoG 분석과 독립된 관찰 기능이다. 카메라 기록은 FoG 모델의 입력·학습 데이터로 자동 전달되지 않으며, 이 기능이 진동·레이저를 제어하지 않는다.

```text
웹캠 허용 → 브라우저의 별도 분석 작업(Worker) → MediaPipe 관절 위치
       → 화면 평면의 각도 계산 → 촬영 품질 확인 → 15초 기록
       → 사용자가 저장 → PC의 비공개 JSON 기록
       → 같은 조건의 개인 기준선 비교 / 외부 각도계 오차 확인
```

이는 관절 움직임을 관찰하고 측정 방법을 검토하기 위한 연구용 구현이다. 질환 진단, 치료 처방, 임상적 정상 범위 판정 또는 치료 효과가 검증된 의료 도구가 아니다. 이전보다 관찰 범위가 커졌다고 건강이 개선됐다고 판정하지 않는다.

## 바로 사용하는 순서

### 정면·좌측면·우측면을 하나의 자료로 통합하기

1. 아래 측정 설정에서 `P01` 같은 측정 코드를 확인한다. 같은 사람이면 세 방향에서 같은 코드를 사용한다.
2. 화면 위 **3방향 측정 세트**에 이름(예: `9월 9일 오전 관절 관찰`)을 입력하고 **새 세트 만들기**를 누른다.
3. **정면 촬영**을 누르고 관찰 관절·자세를 선택한다. 방향 확인 → 15초 기록 → **기록 저장**을 하면 원본 기록과 세트 연결이 함께 저장된다.
4. **좌측면 촬영**, **우측면 촬영**을 같은 방식으로 진행한다. 방향을 바꿀 때마다 확인란을 다시 체크한다. 한 방향에서 발목·무릎 등 여러 관절을 각각 기록할 수도 있다.
5. 방향 카드에서 저장 수·품질 통과 수를 확인한다. **통합 관절 자료** 표에는 방향, 선택한 관절의 각도/범위, 품질, 촬영 시각·자세·환경이 함께 나온다.
6. **통합 JSON**은 세트 정보·원본 각도 시계열·통합 요약을 하나의 파일로, **통합 CSV**는 모든 연결 기록의 각도 표본을 한 표로 내보낸다. CSV의 시간은 각각의 원본 기록 안에서 경과한 시간이며, 세 방향이 동시 촬영됐다는 뜻이 아니다.

기존 기록도 사용할 수 있다. 세트를 선택한 뒤 아래 **방향별 기록 → 세트에 추가**를 누른다. 다른 측정 코드의 기록은 연결할 수 없다. 연결은 원본 ID를 참조하며 각도를 복사해 숨겨 두지 않는다. **세트에서 빼기**와 **세트만 삭제**는 원본 각도 기록을 지우지 않는다. 원본을 삭제하면 해당 세트에 원본 누락이 표시된다.

새로고침 후에는 같은 측정 코드를 입력하고 **현재 세트** 목록에서 이전 세트를 선택한다. **개별 기록 모드**를 선택하면 새 기록을 세트에 자동 연결하지 않는다. 기록 중 또는 미저장 기록이 있는 동안에는 세트/측정 코드를 바꾸지 못한다. 먼저 저장하거나 **미저장 기록 버리기**를 사용한다. 다른 창에서 세트가 삭제되었다면 새로고침 후 남은 초안을 **개별 기록으로 저장**할 수 있다.

#### 통합 상태의 의미

- 각 방향에 품질을 통과한 기록이 하나 이상 있고 원본 누락이 없으면 `3방향 품질 통과 기록 포함`으로 표시한다. 추가로 포함한 품질 부족 기록의 개별 상태는 그대로 표시한다. 전체 데이터의 임상 정확도 인증이 아니다.
- 정면은 어깨 벌림, 측면은 선택한 쪽 발목·무릎·팔꿈치·몸통–허벅지 관찰에 사용한다. 서로 다른 방향에서 얻은 각도를 평균내거나 3D 관절 각도로 합치지 않는다.
- 촬영 환경·자세·신뢰도·모델·화면 비율이 다르면 주의 문구를 표시한다. 첫 기록과 마지막 기록이 120분 넘게 떨어져 있어도 촬영 시점 주의를 표시한다. 120분은 안내 표시 기준이지 의학적 기준이 아니다.
- 원본이 삭제되거나 30일 보관 기간이 지나면 미완성으로 표시한다. **누락 연결 정리**는 사라진 기록의 연결만 제거한다. 사진이나 각도를 복구하는 기능은 아니다.
- 한 세트 최대 30개 원본 연결, 세트 최대 30개다. 세트 보관 기간도 생성 후 30일이며 수정해도 연장되지 않는다. 원본 기록은 자신의 저장일부터 별도로 30일 보관한다. 필요하면 만료 전에 내보낸다.
- 데이터 구조는 `측정 세트 → 원본 기록 ID 목록 → 방향별 각도 시계열·조건`이다. `set-<UUID>.json`에는 이름·측정 코드·연결 ID·수정 버전만 저장한다. 원본 영상·음성은 추가로 저장하지 않는다.

추가 구현 파일: `src/mediapipe/rom-sets.js`는 자료 묶음·요약·JSON/CSV 생성을, `src/mediapipe/set-view.js`는 세트 선택/방향 카드/통합 표를 담당한다. 서버의 `create_set`/`update_set` 요청과 `save_session`의 `setId`·`setRevision` 필드가 저장 흐름을 연결한다. 기존 개별 기록 파일을 변환하거나 삭제할 필요는 없다.

#### 저장 잠금 복구

8000·8001이 같은 파일을 동시에 덮어쓰지 않도록 수정 버전과 `.rom-write.lock` 잠금을 사용한다. 충돌하면 새로고침 후 다시 시도한다. 서버가 비정상 종료된 뒤 잠금 오류가 계속되면 **이 프로젝트의 8000·8001 서버가 모두 완전히 종료됐는지 확인한 후**, 비공개 데이터 폴더의 `.rom-write.lock` 파일만 제거하고 서버를 다시 시작한다. 실행 중인 서버가 있을 때 잠금을 지우거나 `session-`/`reference-`/`set-` 기록 파일을 지우면 안 된다. 자동으로 잠금을 훔쳐 덮어쓰는 복구는 하지 않는다.

### 개별 기록부터 시작하기

1. 기존 웹 서버를 새 코드로 시작한다. 이미 옛 서버가 실행 중이면 먼저 해당 StepOn 서버를 종료하고 다시 실행한다. 다른 Node 프로그램까지 모두 종료하지 않는다.
2. 노트북 Chrome/Edge에서 [MediaPipe 전용 화면](http://127.0.0.1:8000/?view=mediapipe&preview=1&mobile=0&esp32=0&ai=0)을 연다. 이 주소는 센서·FoG 연결 없이 카메라만 시험한다. 8001은 디자인 편집 모드라 실제 카메라 버튼을 실행하지 않는다.
3. **웹캠 사용 동의 → 웹캠 켜기 → 브라우저 카메라 권한 허용**을 누른다. 마이크 권한은 요청하지 않는다.
4. 실명 대신 `P01` 같은 측정 코드를 정한다. 다른 사람을 측정하면 코드를 바꾼다. 카메라 위치·거리·높이가 달라지면 촬영 환경 코드도 바꾼다.
5. 정면/좌측면/우측면, 관찰할 관절, 앉아서/서서 측정을 선택한다. 좌우는 **촬영되는 사람 본인 기준**이다. `거울 보기`는 화면만 좌우 반전하며 기록의 좌우를 바꾸지 않는다.
6. 한 사람만 보이게 하고 선택한 신체 방향과 관절이 잘 보이는지 확인한 뒤 확인란을 체크한다. `측정 가능`이 표시되면 `15초 기록 시작`을 누른다. 편안한 범위에서 움직이고 불편하면 즉시 중단한다.
7. 결과를 확인하고 **기록 저장 → 개인 기준으로 지정**을 누른다. 품질 조건을 통과한 기록만 기준선으로 지정할 수 있다. 다른 방향·관절도 각각 반복한다.
8. 이후 같은 조건에서 다시 기록하면 이전 기준의 범위와 현재 범위, 차이(°)를 비교할 수 있다. `방향별 기록`에서 이전 기록을 선택하거나 CSV/JSON으로 내보낸다.

ESP32 Wi-Fi에 연결하지 않아도 카메라만 사용할 수 있다. ESP32와 연결했더라도 모델 파일이 준비돼 있으면 인터넷 없이 사용할 수 있다. `esp32=0`과 `ai=0`은 이 페이지의 센서/AI 연결을 끄는 URL 옵션이며, ESP32 자체에서 이미 실행 중인 출력 동작까지 중지하는 명령은 아니다.

### 서버 실행 명령

프로젝트 루트에서 Node.js가 설치된 환경이라면 다음 명령을 실행한다. 이 터미널은 서버 실행 중 열어 둔다.

```powershell
node cap_web/dev-server.mjs 8000 127.0.0.1
```

현재 Codex PC에서 `node` 명령을 찾지 못하면:

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" cap_web/dev-server.mjs 8000 127.0.0.1
```

프로젝트의 `run.bat`을 사용하면 기존처럼 8000·8001을 함께 실행한다. PC IP를 사용하는 일반 HTTP 주소에서는 웹캠 권한이 제한될 수 있다. 이 버전의 기록 API도 PC의 `localhost`/`127.0.0.1` 접속만 허용하므로 **노트북 자체에서 사용**한다.

## 방향별 무엇을 측정하는가

| 방향 | 관찰값 | 필요한 위치 및 해석 |
|---|---|---|
| 정면 | 왼쪽·오른쪽 어깨 벌림 | 팔꿈치–어깨–골반 사이 각도. 팔을 카메라 화면과 같은 평면에서 움직인다. |
| 좌측면 | 왼쪽 정강이–발, 무릎, 팔꿈치, 몸통–허벅지 | 왼쪽 옆면을 카메라로 향한다. 주로 사용할 관절을 하나 선택한다. |
| 우측면 | 오른쪽 정강이–발, 무릎, 팔꿈치, 몸통–허벅지 | 오른쪽 옆면을 카메라로 향한다. 좌측 기록과 따로 저장한다. |

- 발목 관찰값: **발목→무릎 벡터와 뒤꿈치→발끝 벡터 사이의 각도**. 중립이 대략 90°로 보일 수 있지만 임상적 배굴/저굴 각도와 동일하지 않다. 발이 작게 보이거나 가려지면 측정을 보류한다.
- 무릎·팔꿈치: `180° − 세 점의 내각`. 일직선이면 약 0°로 표시된다.
- 몸통–허벅지: `180° − 어깨–골반–무릎 내각`. 몸통 기울임을 포함할 수 있어 골반을 고정한 독립 고관절 검사로 해석하면 안 된다.
- 정면 기록 하나에서 측면 발목 굽힘을 정확하게 얻으려 하지 않는다. 정면/좌측면/우측면을 합성한 3D 모델도 만들지 않는다.
- `x × 영상 너비`, `y × 영상 높이`로 좌표를 변환한 뒤 각도를 계산한다. 화면 비율이 다른 정규화 좌표를 그대로 사용해 생기는 각도 왜곡을 줄인다.
- 범위는 **유효 각도의 5~95 백분위 차이**다. 이상치 한두 프레임의 영향을 줄이기 위한 관찰 범위이며 임상적 최대 가동범위와 같지 않다.

## 검증 기능과 품질 조건

### 자동 측정 품질 필터

- 화면에 한 사람이 있고 촬영 방향을 사용자가 확인해야 한다. 좌측/우측면을 완전히 자동으로 구분한다고 가정하지 않는다.
- 선택한 관절과 몸통의 랜드마크 신뢰도·화면 내부 위치·선분 크기를 확인한다. 기본 신뢰도 하한은 0.75다.
- 어깨/골반 폭과 몸통 길이의 비율로 정면/측면을 대략 점검한다. 이는 체형과 자세 영향을 받는 **경험적 필터**이며 검증된 임상 기준이 아니다.
- 지연되거나 누락된 추정은 0°로 채우거나 같은 프레임으로 반복 기록하지 않는다.
- 기록은 5 Hz, 목표 길이는 15초다. 유효 표본 40개 이상, 유효율 70% 이상, 완료 길이 14.5~17초, 중단 없음인 경우만 개인 기준 비교에 사용한다.
- 카메라 분석 목표는 최대 약 15회/초이며 실제 속도는 PC 성능에 따라 달라진다. ESP32의 64 Hz 센서 스트림과 별개다.
- 측정 코드·촬영 방향·관절·앉기/서기·촬영 환경 코드·신뢰도 하한·프로토콜·모델 버전·영상 비율이 같아야 기준선과 비교한다. 실제 카메라 위치까지 자동 보정하지 않으므로 환경 코드를 정직하게 구분해야 한다.

### 외부 각도계 비교

1. 안전하게 정지 자세를 유지하고 `현재 각도 고정`을 누른다.
2. 가능하면 보조자와 함께 **동일한 선분·평면 정의**로 외부 각도계 값을 측정한다. 자세가 바뀌었으면 다시 고정한다.
3. 외부 측정값을 입력하고 같은 자세 확인란을 체크한 뒤 `비교값 저장`을 누른다.
4. 같은 촬영 조건의 표본 수, 평균 절대 오차(MAE), 평균 편향, 최대 절대 차이를 확인한다. 잘못 입력한 비교값은 삭제할 수 있다.

단일 참조값이나 자체 입력만으로 정확도를 인증할 수 없다. 사람·각도·반복 횟수·촬영 조건을 정한 별도 비교 실험이 필요하며, 실제 치료 효과 검증에는 전문가가 설계한 별도의 평가가 필요하다. 이 구현은 합격/불합격 임상 오차 기준을 임의로 정하지 않는다.

## 저장과 개인정보

- 기본 경로: 프로젝트 루트의 `.stepon-data/mediapipe/`. 웹 공개 폴더인 `cap_web` 밖에 있으며 Git에서 제외한다.
- `session-<UUID>.json`: 측정 코드, 촬영 조건, 시각, 유효 여부, 관절 각도 시계열, 요약값.
- `reference-<UUID>.json`: 같은 자세의 추정 각도와 사용자가 입력한 참조값.
- `baseline-<조건 해시>.json`: 개인 기준선으로 지정한 기록 ID.
- **원본 영상·사진·음성·전체 랜드마크를 파일이나 서버에 저장하지 않는다.** 영상은 브라우저와 분석 Worker의 메모리에서만 처리한다.
- 8000·8001은 같은 PC 기록 저장소를 사용한다. 기본 최대 300개 움직임 기록/100개 참조값, 저장 후 30일이 지나면 다음 저장소 접근 시 삭제한다.
- 개별 삭제, 전체 삭제, 현재 측정 코드의 JSON 내보내기, 선택한 기록의 CSV 내보내기를 지원한다. 삭제한 기록은 앱에서 복구할 수 없으므로 필요하면 먼저 내보낸다. 다운로드 파일은 자동 삭제되지 않는다.
- 로그인·사용자별 암호화 저장소는 아니다. 같은 PC 계정 사용자에게 보일 수 있으므로 개인 PC에서 비식별 측정 코드를 사용한다.
- 저장 위치를 바꾸려면 서버 시작 전 `STEPON_ROM_DATA_DIR`에 공개 웹 폴더 밖의 전용 폴더를 지정한다. 저장된 JSON을 수동으로 수정하지 않는다.

## 모델 준비와 테스트

현재 로컬 모델 파일을 포함했다. 파일이 누락된 PC에서는 인터넷 연결 상태에서 한 번 실행한다.

```powershell
node cap_web/tools/setup-mediapipe.mjs
```

MediaPipe Tasks Vision 1.0.1, Pose Landmarker Lite float16 모델을 고정해서 사용한다. 라이브러리/WASM/모델은 약 29 MB다. `vendor/mediapipe/manifest.json`에는 출처·크기·SHA-256을 남기며 이후 추론 시 CDN을 호출하지 않는다.

자동 테스트:

```powershell
node --test cap_web/tests/*.test.mjs
```

별도 임시 폴더/임시 포트를 사용하므로 실제 저장 기록을 지우거나 웹캠을 켜지 않는다. 각도 계산, 품질·기준선 분리, 파일 보존·삭제·보관 기간, API, 앱 JS, 로컬 자산 무결성을 확인한다. Worker 추론 테스트는 가짜 추론기로 메시지·자원 정리만 검증하며 **실제 웹캠/모델 정확도 검증을 대신하지 않는다**.

### 사용자가 직접 확인할 최종 체크리스트

- 카메라 동의 전/페이지 진입 시 웹캠이 켜지지 않는다.
- 권한을 허용하면 영상과 관절선이 겹쳐 표시되고, 거부하면 안내가 표시된다.
- 정면·좌측면·우측면 선택에 따라 관절 목록과 촬영 안내가 바뀐다.
- 화면에서 벗어나거나 관절을 가리면 숫자가 `—`로 바뀐다.
- 한 방향을 15초 기록하고 저장한 후 새로고침해도 기록이 남는다.
- 개인 기준 지정 후 동일 조건 기록은 비교되며 다른 사람/자세/환경 기록은 섞이지 않는다.
- 각도 고정→외부 각도계 입력→저장 후 오차 수치가 표시된다.
- 카메라 끄기, 다른 메뉴 이동, 브라우저 탭을 다른 곳으로 전환하면 카메라 사용이 종료된다. 진행 중 기록은 비교 제외된다.
- 인터넷을 끊은 상태에서도 로컬 모델이 초기화된다. 발목이 작거나 가려질 때는 거리·구도·조명을 조정한다.

`기록 API가 아직 없습니다`는 옛 서버가 실행 중이라는 뜻이다. 서버를 재시작하고 화면을 새로고침한다. 카메라 초기화 실패 시 권한·다른 앱의 카메라 점유·모델 파일 유무·브라우저 지원을 확인한다.
